## 📝 技术决策

| 决策 | 原因 | 影响 |
|------|------|------|
| 字典采用单层扁平表（soc_dicts）而非两级（类型表+值表） | 需求简单，dict_type 天然分类，减少 JOIN | 1 张表搞定全部枚举，查询性能更好 |
| 前端字典用 Pinia Store 缓存 + 登录后预加载 | 字典数据量小（<100 条），运行时不应再发请求 | 提升页面响应速度，避免重复请求 |
| 字典与系统配置分两张表而非合并 | 字典需要排序/颜色/启用/禁用等元数据；系统配置是 KV 单一值 | 业务模型清晰，扩展性更好 |
| system_config 路由顺序：/categories 必须先于 /{id} | FastAPI 按声明顺序匹配，否则 categories 会被解析为 int 失败 | 接口语义清晰，避免误匹配 |
| asset_sync 同步状态用 dict_code（online/offline）而非中文 | 字典是唯一真相源，前端展示走 dictStore 翻译 | 数据规范，前端组件不再需要做中英文映射兜底 |
| menu_service 取所有菜单而非仅 is_visible=True | 隐藏菜单（资产详情）仍需注册为路由 | 修复了隐藏页面 404 的 Bug |
| 数据迁移脚本与种子数据分离 | 种子数据幂等可重复执行；迁移是一次性的脏数据修复 | 部署流程更清晰 |
| 写操作（dict/system_config）统一要求 admin 角色 + 审计日志 | 系统级配置不应被普通用户误改 | 安全性 + 可追溯 |
