1. **菜单 path 单数化迁移**（防御性 SQL 改造 + 测试守护）
   - SQL/init 脚本：`/system/users` → `/system/user`、`/system/roles` → `/system/role`、`/system/menus` → `/system/menu`、`/system/audit` → `/system/audit-log`，对齐前端 `RoutesAlias` 契约

   - 新增 `tests/test_menu_path_singular.py`（5 用例）作为防回归网：

2. **角色菜单 API 重写为树形 + meta 嵌套结构**
   - `app/api/roles.py::get_role_menus` 之前返回"扁平 + 顶层 authList"，前端 `auth.vue` 渲染 el-tree 报错
   - 重写后：复用 `app/api/menus.py::_build_menu_with_auth`，返回 `{role_id, menu_ids, menus: [树形]}`，每个节点 `meta.{title,icon,authList,hasPermission}` 嵌套
   - 关键修复：`_build_menu_with_auth` 始终暴露 `children` 数组（即使为空），前端 el-tree 用 `children.length===0` 判断叶子
   - `roles.py` 顶部 `menu_service.get_menu_tree(role_id=...)` 复用 service 的角色过滤逻辑（保留父菜单 if 任意子被分配）
   - 新增 `tests/test_role_menus_api.py`（7 用例）：
     - 顶级菜单含 `children` 数组
     - `meta.authList` 长度/字段契约
     - `hasPermission` 正确反映按钮授权（view=True / delete=False）
     - 空角色返回 `menus=[] / menu_ids=[]`
     - 分配后 GET 的 roundtrip 一致
     - 非 admin 调用通过 envelope 业务码 403 拒绝（HTTP 恒 200）
     - 不存在的 role_id 通过业务码 404 拒绝

3. **测试基础设施复用**
   - 全部走 `app.core.database.test_engine`（`AI-miniSOC-db_test`），与生产 `DB_NAME=AI-miniSOC-testdb` 完全隔离
   - conftest 的 `db_session` 仍负责 `create_all` / `drop_all`；`client` 走 `app.dependency_overrides[get_db] = ...` 注入测试 session
   - 测试内自建 `code='admin'` 的 role 是必需的 —— `User.is_admin` 是 `@property` 派生自 `role.code == 'admin'`，`is_superuser` 不参与判断
