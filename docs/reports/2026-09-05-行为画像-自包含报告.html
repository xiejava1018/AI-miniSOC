⚠️ 关于本报告的生成方式：Bash 执行环境在本会话临时不可用，无法运行 Python 报告生成器。 本报告由采集引擎已算出的结果（behavior_profile_data.json）内联、浏览器端 JS 直接渲染而成， 数据与后端采集完全一致。引擎共对 8 个 IP 完成画像，此处呈现 4 个数据最完整、特征最鲜明的主体 （.8 你的开发机 / .100 AI 工作站 / .17 NAS 下载机 / .25 追剧手机）； 其余 4 个为服务器/扁平机器流量（含 owner=佳佳 的 Redmi-Note-11 手机），画像偏薄，未详述。

数据说明与已知偏差（PM 视角）

  • 采集方式：时段统计以 Loki 原始日志时间戳逐条计数，未用 count_over_time 聚合（实测该聚合 step=1h 下存在窗口标签错位与边界重复计数，会使时段画像失真）。
  • 时间窗：Loki 仅保留 7 天，本画像为最近 7 天，无法反映月度/季度长期节律。
  • 行为分层：访问分「主动行为 / 系统背景 / 广告追踪」三层。NTP 校时、DNS、系统更新、遥测上报、广告 SDK 回传属机器行为，已隔离；画像标签与兴趣分类只基于主动行为。
  • 分类方法：域名分类为关键词规则匹配，存在误判（如 apple.com 同时承载系统与个人服务；countly.mail.163.com / woodcattle-qz.dashi.163.com 实为网易邮箱客户端心跳/遥测，被归为「工作办公」）。
  • 两个关键噪声：① .8 的「工作办公 95.6%」主要是网易邮箱心跳（countly + woodcattle 合计占 95%），并非真实办公行为，解读时须扣除；② .17 的小时曲线几乎完全平直（~4100/小时），属 NAS 的 STUN/隧道/P2P 机器轮询，不是人的作息——这类「扁平曲线」设备不适合做人类行为画像。
  • IP ≠ 人：主体是 IP/设备，同一 IP 背后可能多人共用（如家庭/共享设备），需结合认证日志建立身份管道才能落到自然人。
  • 覆盖偏差：画像丰富度取决于设备是否持续在线；离线设备画像偏薄，不能据此推断使用者「行为简单」。
