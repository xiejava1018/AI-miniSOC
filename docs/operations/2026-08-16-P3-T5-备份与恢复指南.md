# AI-miniSOC 备份与恢复指南（P3-T5）

> 生效日期：2026-08-16｜依据：`2026-08-16-P4数据可靠性实施工作计划.md` P3-T5

## 一、目标

确保数据可靠性最后一道兜底：**数据丢了能回**。

- 全量备份（schema + data）可执行、可恢复
- 保留策略明确，自动轮转
- RPO / RTO 目标有据可依

## 二、PostgreSQL 备份

### 2.1 备份脚本
- 位置：`src/backend/scripts/pg_backup.py`
- 跨平台纯 Python 实现，无需 `pg_dump`
- 输出：`src/backend/backups/AI-miniSOC_YYYYMMDD_HHMMSS.sql`（自定时间戳）

### 2.2 使用方法

```bash
# 默认（保留最近 7 份）
cd src/backend
./venv/bin/python scripts/pg_backup.py

# 自定义保留份数
./venv/bin/python scripts/pg_backup.py --keep 30

# 自定义输出目录
./venv/bin/python scripts/pg_backup.py --out /data/backups
```

### 2.3 保留策略
- 默认保留 **7** 份（最近一周每天一份）
- 生产建议：保留 **30** 份（最近一个月）
- 备份文件大小：实测 ~360MB（含 soc_vulnerabilities 等大表）

### 2.4 自动调度建议
通过 crontab 添加（生产环境）：

```cron
# 每天凌晨 3 点全量备份，保留 30 份
0 3 * * * cd /path/to/AI-miniSOC/src/backend && /path/to/venv/bin/python scripts/pg_backup.py --keep 30 >> /var/log/aisoc_backup.log 2>&1
```

### 2.5 恢复方法

```bash
# 1. 选最近一份备份（按时间戳）
ls -lt src/backend/backups/AI-miniSOC_*.sql | head -1

# 2. 恢复（覆盖当前库；务必先停服或确认无写入）
psql -h $DB_HOST -U $DB_USER -d $DB_NAME < backups/AI-miniSOC_YYYYMMDD_HHMMSS.sql

# 或用 docker / k8s exec 进入容器执行
kubectl exec -it aisoc-postgres -- psql -U aisoc -d AI-miniSOC < AI-miniSOC_20260816_201525.sql
```

### 2.6 PITR（Point-in-Time Recovery）— 进阶
当前 MVP 阶段未启用 PITR。生产关键期建议：
- 启用 PostgreSQL `wal_level=replica`
- 配置 WAL 归档到独立存储（OSS / S3）
- 评估采用云厂商 PG 托管服务（自动 PITR）

## 三、Loki 备份策略

### 3.1 数据特点
- 7 天滚动保留（`LOKI_RETENTION_DAYS=7`）
- 日志体量大（24h 实测 20 万+ 条 TP-Link 路由上网行为）
- 原始日志数据，非结构化

### 3.2 备份建议
- **冷数据**：保留 7 天窗口足够业务查询，无需额外备份
- **关键审计日志**：通过 `loki_client` 周期性查询并落库到 `soc_audit_logs`（已有）
- **配置备份**：`/etc/loki/config.yaml` 走 git 管理

### 3.3 恢复
Loki 数据丢失 = 重新采集（前提是源端仍在推送）：
- 检查 TL-R479GP-AC 路由器 syslog 配置（已知问题：192.168.0.2 日志凌晨 1:27 后中断，见 P4 方案 §已知问题）
- 临时方案：手动补跑 `loki_bootstrap.sh`（如有）

## 四、OpenSearch 备份策略

### 4.1 数据特点
- Wazuh 检测出的结构化告警 / 脆弱性数据
- 164+ 索引（wazuh-alerts-4.x-* + wazuh-states-vulnerabilities-* + 监控索引）
- 合计约 136 万文档

### 4.2 备份建议
- **索引保留**：OpenSearch ILM 策略（Index Lifecycle Management）自动管理
- **快照**：通过 OpenSearch Snapshot API 定期备份到 S3 / OSS
- **配置备份**：`/etc/wazuh-indexer/opensearch.yml` 走 git 管理

### 4.3 恢复
- 告警/脆弱性数据可通过 OpenSearch Snapshot 恢复
- 关键告警已落库 `soc_ai_analyses` + `soc_vulnerabilities`（PG 侧兜底）
