# AI-miniSOC 资产管理 AI 能力建设方案

> **核心主线**：从"台账思维"跃迁到"本体治理"——把资产从一行行台账记录，升级为可对齐、可推理、可审计的资产本体图谱，让 AI 在图上完成融合、稽核、研判、优先级与整改闭环。

> **S4 范围纪律（产品边界，2026-10-01 重启）**：定级备案本期仅做「辅助定级与差距分析」，不做全闭环备案状态机。治理红线：① 等保定级为法律判定，系统**只建议、不裁决**，建议结果须走"确认工作台"人工确认（复用 S1 确认机制）；② 对外表述限"辅助定级与差距分析工具"，**不得承诺"保证等保合规"**（Liability）；③ 平台 AI-miniSOC **自身**等保备案是部署合规事项，归运维/合规手册，与此客户资产定级备案功能严格分账。后续若客群出现等保三级及以上 / 关基运营者（原 T1）、合同明确要求备案管理（原 T2）、或平台自合规需纳入统一视图（原 T3），S4 自 Phase 0 平滑升级至 Phase 1–3（差距分析 / 报告 / 备案跟踪）。

### 3.2 八维画像数据模型（设计）

```python
# app/services/asset_profile.py（设计伪代码，非现代码）

@dataclass
class AssetProfile:
    # ① 身份维
    identity: AssetIdentity
    # ② 归属维
    ownership: AssetOwnership
    # ③ 技术维
    technology: AssetTechnology
    # ④ 暴露维
    exposure: AssetExposure
    # ⑤ 脆弱维
    vulnerability: AssetVulnerability
    # ⑥ 威胁维
    threat: AssetThreat
    # ⑦ 合规维
    compliance: AssetCompliance
    # ⑧ 行为维
    behavior: AssetBehavior

    # AHS 健康分
    ahs_score: int          # 0-100
    ahs_evidence: List[EvidenceItem]

    # 画像可信度
    profile_confidence: float  # 0-1
    missing_dimensions: int
```

### 3.3 AHS 算法

```
AHS = 100 − (暴露风险 × w1 + 脆弱 × w2 + 威胁 × w3 + 合规缺口 × w4 + 行为异常 × w5)
       × 资产关键性系数

资产关键性系数 = f(业务影响, 数据敏感度, 等保等级)
                = 三维加权（BIA 5 档 × CIA 5 档 × 等保 5 级）
                范围 0.8 ~ 1.5
```

> **AHS 与既有 `risk_score` 的关系（明确）**：二者并存、不互相替换。`risk_score`（`AssetRiskService`，四维评分：暴露 30% + 健康 25% + 告警 25% + 重要性 20%，含数据稀疏降级）是既有的底层资产风险分，持续运行；AHS 是本次新增的**八维资产健康分（0-100，越高越健康）**，将 `risk_score` 作为"脆弱/威胁"维的核心输入之一（融入 `vulnerability`/`threat` 权重），并叠加合规、行为两维与证据链。下游展示与排序优先用 AHS，根因下钻回到 `risk_score` 明细。
>
> **等保/合规数据缺失降级（S4 Phase 0 接入后生效，作为兜底）**：AHS 公式含 `合规缺口×w4`（L213）与关键性系数的`等保等级`维（L216-217）。S4 Phase 0（OH-4.4a 建议引擎 + 确认工作台人工确认）落地后，`protection_level` 才有自动建议来源。兜底：个别资产等保字段仍空时，`等保等级`空 → 该维取中性值（不放大/不报错）；`合规缺口 w4` 无数据 → 权重并入其余维（重归一化）。禁止因合规数据缺失导致 AHS 报错或失真。

> 与本地 `app/core/criticality.py`（commit c52fb86，2026-09-14 三维度重要性重构）同构——本次直接把其纳入画像输入。

4. **采集器 CI/CD 覆盖**——本次新增的 **TP-Link NAT 扩展**，**必须在 `deploy_collectors.sh` 同步加健康门禁**（CLAUDE.md v3.0 CI/CD 节，2026-08-23 记录；原「2026-08-23 续八」标题已在 v3.0 重构中并入主题节）；Wazuh 已在门禁内，无需额外接入。
5. **本地三库严格分离**——本体迁移、AHS 计算、图谱重建都需考虑测试库隔离（CLAUDE.md §1.7）。
6. **X1 权限矩阵**——新加的 S2/S5/S11/S12 端点必须接权限（admin/auditor/viewer 三档）。
7. **`sync_client` 假绿教训**——CLAUDE.md §4.13（已知未修）：同步采集器曾把 `body.code=400` 当成功。tplink 使用的 collector-framework sync_client 已正确处理 code≠200（重试后抛错），wazuh 侧按 §4.13 自查；本次采集器新增必须遵守 envelope 口径。
8. **新增 MCP 工具必须走 schema 验证**——CLAUDE.md "service 测过了路由未必通"，MCP tools 同样需路由级端到端实测。
