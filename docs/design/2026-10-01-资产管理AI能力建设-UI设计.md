## 0. 设计目标与原则（Why 优先）

资产管理 AI 能力建设的核心不是"多几个页面"，而是把 **AI 在资产图谱上做的融合、研判、推理、整改** 变成**人能理解、能干预、能审计**的界面。因此 UI 设计遵循 5 条原则：

| 原则 | 含义 | 反模式 |
|---|---|---|
| **本体可对齐** | 任何资产展示都能追溯"这是本体哪一类/哪个属性" | 散列表格无本体语义 |
| **推理可解释** | AI 结论必须带证据链 + 置信度，可下钻 | "AI 说高危"无来源 |
| **数据可补齐** | 空值/推断项显式呈现，提供"确认/修正"入口 | 静默造假或让人从零填表 |
| **闭环可追踪** | 发现→定责→处置→验证全程可见、可回查 | 工单与资产脱节 |
| **权限可分级** | admin/auditor/analyst/viewer 看到的能力不同 | 全量暴露 |

**目标用户与角色**：

| 角色 | 关注 | 关键页面 |
|---|---|---|
| 安全运营分析师 analyst | 暴露面、攻击路径、告警关联 | 图谱、暴露面、ATT&CK、数字员工 |
| 资产管理员 asset_manager | 数据补齐、归属、业务系统 | 确认工作台、完整度卡、业务系统 |
| 审计员 auditor | 证据链、闭环留痕、定级备案稽核 | 本体对齐、六步闭环、定级备案稽核 |
| 管理员 admin | 采集器、AI 资产、权限 | 采集器、AI 资产、菜单权限 |
| 观察员 viewer | 只读看板 | 总览、看板 |

## 2. 设计系统（Design Tokens）

遵循 **Element Plus 默认浅色主题**（IDE 当前为 light），叠加 SOC 语义色。所有色值用 CSS 变量，便于后续切换暗色。

### 2.1 色彩

| Token | 值 | 用途 |
|---|---|---|
| `--c-primary` | `#409EFF` | 主操作、导航选中 |
| `--c-bg` | `#F5F7FA` | 内容区背景 |
| `--c-panel` | `#FFFFFF` | 卡片/面板 |
| `--c-border` | `#E4E7ED` | 分割线 |
| `--c-text` | `#303133` | 正文 |
| `--c-text-2` | `#909399` | 次要文字 |
| **严重 critical** | `#F56C6C` | 紧急/严重漏洞、高危资产 |
| **高 high** | `#E6A23C` | 高危 |
| **中 medium** | `#F0C020` | 中危 |
| **低 low** | `#67C23A` | 低危/健康 |
| **置信高 ≥0.9** | `#67C23A` 实线 | 已验证边 |
| **置信中 0.6–0.9** | `#409EFF` 实线 | 规则归一边 |
| **置信低 <0.6** | `#C0C4CC` 虚线 | 推断边（不入攻击路径） |

### 2.2 布局与栅格
- 三栏框架：顶部条(56px) + 左侧导航(220px 可折叠) + 内容区。
- 内容区栅格 24 列，卡片间距 16px；图表最小高 320px。
- 详情/图谱用全宽；列表/工作台用容器宽 1280px 居中。

### 2.3 字体
- 界面：`system-ui, "PingFang SC", "Microsoft YaHei", sans-serif`
- 数据/代码：`ui-monospace, "SF Mono", Consolas, monospace`
- 字号：标题 18/16、正文 14、次要 12。

### 2.4 图可视化规范（继承 AKG 原型）
- 节点按资产类型着色（服务器/终端/网络设备/业务系统/人/AI资产）。
- 边按置信度三档渲染（上表）。
- 攻击路径：红色高亮路径 + 序号 + 每跳置信度。
- 画布交互：拖拽、缩放、点击节点抽屉出详情、框选批量。

**关键发现（落地成本重估）：**
1. **6 个页面（含 compliance，S4 重启后注册）已写完在磁盘上，仅因未注册 `asyncRoutes` 而 404**——真正的"接线"工作（路由 + `routesAlias` + 后端 `soc_menus` 种子 + 权限）成本极低，UI 本身已就绪。

## 6. 关键交互流程

### 6.1 数据补齐闭环
```
推断引擎(F1) → 候选暂存(F2) → 确认工作台(只显<0.7)(4.5.1)
   → 人工确认/修正/忽略(4.5.1) → 落库+级联(F6) → 完整度卡重算(4.5.2)
```
高置信(≥0.9)自动落库不推人；低置信推人复核 → 把"填 73 台"降为"复核 20 台低置信"。

### 6.2 数字员工工具调用
```
选工具(Workspace) → 对话提问 → 后端工具返回 evidence[]+confidence
   → 证据链回显(4.7.1) → [采纳]落库 / [转工单]跳4.9.1 / [定位图谱]跳4.4
```

### 6.3 整改闭环（六步）
```
发现(告警/推断) → 画像(4.3) → 定责(确认工作台4.5.1) → 处置(工单4.9.1)
   → 验证(复测/reopen) → 复盘(六步4.9.2) → 指标进闭环看板(4.9.3)
```
