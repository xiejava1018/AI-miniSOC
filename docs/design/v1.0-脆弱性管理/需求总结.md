## 背景

### 当前痛点
1. **不知道资产有哪些漏洞** - 缺乏统一的漏洞管理界面
2. **知道了漏洞也不知道如何修复** - 缺乏修复建议和优先级指导
3. **扫描工具分散** - Wazuh SCAP和OpenVAS各自独立，缺乏统一管理

### 业务需求
- **主动防御** - 在攻击者利用漏洞前发现并修复
- **提高运维效率** - AI辅助决策，快速定位需要优先处理的漏洞
- **统一管理** - 整合多个扫描器，提供统一的漏洞视图

---

## 目标

### 核心目标
构建一个完整的脆弱性管理模块，实现：
- ✅ 漏洞扫描（Wazuh SCAP + OpenVAS）
- ✅ 漏洞结果展示（列表、详情、统计）
- ✅ AI风险排序（告诉用户优先修复哪5个）
- ✅ 修复建议（提供具体的修复方案）

### 成功指标
- 漏洞发现率提升 80%
- 漏洞修复时间缩短 50%
- 安全事件响应速度提升 60%

## 功能范围

### ✅ 要做什么

#### 1. 漏洞扫描能力
- **Wazuh SCAP集成**
  - 利用现有Wazuh SCA模块
  - 支持CIS Benchmarks、STIG等合规标准
  - 自动同步已安装软件包的漏洞信息

- **OpenVAS深度扫描**
  - 封装为独立服务（Kali Linux）
  - 提供REST API供AI-miniSOC调用
  - 支持认证和非认证扫描
  - 可调度扫描任务

#### 2. 漏洞维度视图（脆弱性管理模块）

**页面1: 脆弱性概览**（默认页面）
- **统计概览**
  - 严重/高危/中危/低危漏洞统计卡片
  - 较上周变化趋势
  - 点击卡片跳转到对应筛选的漏洞列表

- **AI智能建议**
  - 优先修复Top 5建议
  - 基于多维度分析：CVSS + 威胁情报 + 资产价值 + 暴露面
  - 提供风险原因和修复建议
  - 一键跳转到漏洞详情

- **快速操作**
  - 启动全量扫描（Wazuh + OpenVAS）
  - 查看漏洞列表（跳转）
  - 导出扫描报告

- **趋势图表**（可选）
  - 30天漏洞发现趋势
  - 修复进度统计

**页面2: 漏洞列表**（详情和操作页面）
- **扫描操作面板**
  - Wazuh SCAP快速扫描
  - OpenVAS深度扫描
  - 定时扫描任务配置
  - 扫描进度实时显示

- **筛选工具栏**
  - 严重程度筛选（严重/高危/中危/低危）
  - 扫描器筛选（Wazuh/OpenVAS）
  - 状态筛选（未修复/修复中/已修复）
  - 搜索功能（CVE、漏洞名称、资产）

- **漏洞列表表格**
  - 分页展示
  - 显示CVE、严重程度、CVSS评分、受影响资产、扫描器、状态
  - 支持排序
  - 点击查看详情

**导航结构**:
```
脆弱性管理
├── 脆弱性概览（默认显示）
└── 漏洞列表
```

#### 3. 资产维度视图（资产管理模块集成）
- **资产漏洞标签页**
  - 显示该资产的漏洞统计
  - 该资产的漏洞列表
  - 单个资产的快速扫描

- **AI资产级建议**
  - 针对该资产的修复优先级
  - 最危险的漏洞提示

#### 4. 漏洞详情
- CVE完整信息
- CVSS评分明细
- 受影响资产列表
- 修复建议（具体版本号）
- 参考链接

### ❌ 不做什么

1. **不做漏洞自动修复** - 只提供建议，不自动执行修复操作
2. **不做威胁情报** - 本版本不集成外部威胁情报源（后续版本考虑）
3. **不做漏洞修复跟踪** - 暂不包含修复工单系统（可后续集成）
4. **不做资产管理** - 假设已有资产列表，不重复开发

## 关键决策

### 决策1: 双维度视图设计
**问题**: 脆弱性管理应该以什么为核心组织？
**决策**:
- **漏洞维度**（脆弱性管理模块）- 以漏洞为中心，回答"今天有哪些漏洞要修"
- **资产维度**（资产管理模块集成）- 以资产为中心，回答"这台服务器有什么问题"

**理由**:
- 安全分析师关注"今天要修哪些漏洞"（漏洞维度）
- 运维工程师关注"这台服务器有什么问题"（资产维度）
- 两个维度互补，满足不同角色需求

---

### 决策2: 扫描器架构
**问题**: Kali Linux上的扫描器如何集成？
**决策**: OpenVAS封装为独立服务，提供REST API

**架构**:
```
AI-miniSOC (主系统)
    ↓
脆弱性管理模块
    ↓
扫描器服务 (独立封装)
    ↓
OpenVAS (Kali Linux)
```

**理由**:
- 解耦：OpenVAS可以独立部署、升级
- 安全：扫描器故障不影响主系统
- 灵活：后续可添加其他扫描器（Nessus、Nmap等）

---

### 决策3: AI排序算法
**问题**: 如何决定漏洞的优先级？
**决策**: 多维度综合评分，不依赖单一CVSS分数

**评分因子**:
1. **CVSS基础分** (40%)
2. **资产关键度** (25%) - 关键服务器权重更高
3. **暴露面** (20%) - 公网资产风险更高
4. **在野利用** (15%) - 有在野利用记录的漏洞优先级最高

**理由**:
- CVWS分数不能反映业务价值
- 核心业务服务器的低危漏洞 > 非关键资产的高危漏洞
- 实战导向：有在野利用的漏洞最危险

---

### 决策4: 技术栈选择
**问题**: 使用什么技术栈实现？
**决策**: 完全遵循AI-miniSOC现有技术栈

**前端**:
- Vue 3 + TypeScript
- Element Plus UI组件库
- Pinia状态管理
- Vite构建

**后端**:
- FastAPI (Python)
- SQLAlchemy ORM
- PostgreSQL (数据库)
- Celery (异步任务)

**理由**:
- 保持技术栈一致性
- 降低开发和维护成本
- 复用现有组件和基础设施

---

### 决策5: UI设计风格
**问题**: 如何保持设计一致性？
**决策**: 严格遵循AI-miniSOC现有设计规范

**设计元素**:
- 玻璃态背景 + 模糊效果
- 青色为主色调 (#00D4FF)
- 卡片式布局（16px圆角）
- 渐变按钮和微光效果
- 侧边栏 + 主内容区布局
- **支持明亮/暗黑主题切换**（CSS变量实现）

**主题切换**:
- 使用CSS自定义属性（CSS Variables）定义主题颜色
- 通过`[data-theme="light/dark"]`选择器切换主题
- 主题偏好保存到localStorage
- 所有组件必须适配两种主题

**理由**:
- 用户已熟悉的界面风格
- 降低学习成本
- 统一的产品体验
- 适应不同工作环境的 lighting conditions

---

### 决策6: 页面结构设计
**问题**: 漏洞维度应该采用单页面还是多页面？
**决策**: 拆分为两个独立页面，通过侧边栏导航

**页面划分**:
1. **脆弱性概览**（默认页面）
   - 漏洞统计卡片（严重/高危/中危/低危）
   - AI智能建议（Top 5优先修复）
   - 快速操作入口
   - 30天漏洞趋势图表

2. **漏洞列表**（详情页面）
   - 扫描操作面板（Wazuh SCAP、OpenVAS、定时任务）
   - 筛选工具栏（严重程度、扫描器、状态）
   - 漏洞列表表格（分页）
   - 搜索功能

**导航结构**:
```
侧边栏菜单：
├── 脆弱性管理（分组）
│   ├── 脆弱性概览（active）
│   └── 漏洞列表
```

**交互逻辑**:
- 点击"脆弱性管理"菜单默认显示"脆弱性概览"
- 两个页面通过侧边栏独立切换
- 概览页面提供快速入口跳转到漏洞列表

**理由**:
- 信息密度优化：概览聚焦高层视图，列表聚焦操作
- 性能优化：减少单页面渲染压力
- 用户习惯：安全分析师巡检先看概览，需要时再进入列表
- 可扩展性：后续可轻松添加更多子页面（如报表、配置）

## 技术约束

### 现有系统集成
1. **必须集成Wazuh API**
   - 基础URL: `https://192.168.0.30:55000/api`
   - 认证方式: JWT Token
   - 现有模块: `/alerts`, `/vulnerability`, `/sca`

2. **必须集成资产管理模块**
   - 资产数据来源: `/api/v1/assets`
   - 资产详情页: `/assets/:id`
   - 需要在资产详情页添加"漏洞"标签页

3. **日志存储到Loki**
   - Loki地址: `http://192.168.0.30:3100`
   - 用于存储扫描日志和漏洞历史

### OpenVAS集成约束
1. **服务部署位置**: Kali Linux (IP待定)
2. **API封装**: 需要开发FastAPI服务封装OpenVAS命令
3. **认证**: API Key认证
4. **异步任务**: 使用Celery处理长时间扫描任务

### 数据模型约束
1. **漏洞数据表设计**
   ```sql
   vulnerabilities (
       id UUID PRIMARY KEY,
       cve_id VARCHAR(50) UNIQUE,
       title VARCHAR(500),
       description TEXT,
       cvss_score DECIMAL(3,1),
       severity VARCHAR(20),  -- critical, high, medium, low
       affected_packages TEXT[],  -- JSON数组
       fix_suggestion TEXT,
       scanner VARCHAR(50),  -- wazuh, openvas
       discovered_at TIMESTAMP,
       updated_at TIMESTAMP
   )

   asset_vulnerabilities (
       id UUID PRIMARY KEY,
       asset_id UUID REFERENCES assets(id),
       vulnerability_id UUID REFERENCES vulnerabilities(id),
       status VARCHAR(20),  -- open, in_progress, fixed
       detected_at TIMESTAMP,
       fixed_at TIMESTAMP
   )
   ```

2. **扫描任务表**
   ```sql
   scan_tasks (
       id UUID PRIMARY KEY,
       task_type VARCHAR(50),  -- wazuh_scap, openvas
       target_assets JSONB,  -- {"asset_ids": [...], "ips": [...]}
       status VARCHAR(20),  -- pending, running, completed, failed
       progress INT,
       result_summary JSONB,
       created_at TIMESTAMP,
       started_at TIMESTAMP,
       completed_at TIMESTAMP
   )
   ```

## 用户故事

### 故事1: 安全分析师 - 每日漏洞巡检
**作为**安全分析师
**我想要**每天快速查看系统中的高危漏洞
**以便**优先处理最危险的安全问题

**验收标准**:
- 登录后看到"脆弱性管理"菜单
- 打开页面看到AI建议："优先修复这5个漏洞"
- 每个漏洞包含CVE、CVSS、受影响资产、修复建议
- 可以一键查看详情

---

### 故事2: 运维工程师 - 单资产漏洞排查
**作为**运维工程师
**我想要**查看某台服务器有哪些漏洞
**以便**安排维护窗口进行修复

**验收标准**:
- 在资产详情页看到"漏洞"标签页
- 显示该资产的漏洞统计（严重/高危/中危/低危）
- 可以看到该资产的所有漏洞列表
- 可以对该资产启动单独扫描

---

### 故事3: 安全分析师 - 启动深度扫描
**作为**安全分析师
**我想要**对内网资产进行OpenVAS深度扫描
**以便**发现Wazuh SCAP未能检测的漏洞

**验收标准**:
- 在脆弱性管理页面点击"OpenVAS深度扫描"
- 可以选择要扫描的资产
- 扫描进度实时显示
- 扫描完成后自动刷新漏洞列表

---

### 故事4: 系统管理员 - AI辅助决策
**作为**系统管理员
**我想要**AI告诉我应该优先修复哪些漏洞
**以便**在有限时间内最大化安全收益

**验收标准**:
- AI建议面板显示Top 5优先修复的漏洞
- 每个建议包含风险原因（为什么优先）
- 提供具体的修复建议（升级到哪个版本）
