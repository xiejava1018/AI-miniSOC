## 三、根因分析

KEV 目录的离线快照（`data/cisa_kev_snapshot.json`）是一个 mock 种子集，其 CVE id 形如 `CVE-2026-XXXXX`（虚构未来时间，与真实 Wazuh 上报的 CVE 数据集完全无交集）。

KEV 服务实际拉取的真实目录（`https://www.cisa.gov/.../known_exploited_vulnerabilities.json`）在本环境可达（T12 已验证），但目前**未触发重新同步**，所以表里仍是 mock 快照数据。

**两条修复路径**：
1. 触发一次 KEV 手动同步（POST `/api/v1/vulnerabilities/sync/kev`）让表里塞入真实 CISA KEV 数据；
2. 与 OS 同步的 CVE 比对，按 `cve_id` UPPER 严格匹配，结果应反映真实"在野利用"覆盖。

## 四、验收建议（依赖本探查的后续工单）

## 五、附：探查 SQL

```sql
-- 总数
SELECT COUNT(*) FROM soc_vulnerabilities;
SELECT COUNT(*) FROM soc_cisa_kev;

-- 交集（case-insensitive）
SELECT COUNT(*) FROM soc_cisa_kev k
WHERE EXISTS (SELECT 1 FROM soc_vulnerabilities v WHERE UPPER(v.cve_id) = UPPER(k.cve_id));

-- 前缀分布
SELECT SUBSTRING(cve_id FROM 1 FOR 4) AS prefix, COUNT(*)
FROM soc_vulnerabilities
GROUP BY prefix ORDER BY 2 DESC LIMIT 10;
```
