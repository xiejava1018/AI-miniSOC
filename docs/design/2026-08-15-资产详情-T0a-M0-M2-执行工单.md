## 2. 工单明细

### T0a · 关联键数据质量修复（M0 前置，最高优先级）

| 项 | 内容 |
|---|---|
| **目标** | `wazuh_agent_id` 不重复挂载；加唯一部分索引防复发 |
| **背景** | 设计文档 §1.5 / 风险#6/#8。agent_id 双挂会导致漏洞/告警/应用数据串资产 |
| **修改对象** | `soc_assets` 表；`src/backend/app/models/asset.py` |

**具体步骤：**

1. **【真实环境复核，先做】** 在真实 DB 执行，确认重复键与可疑资产：
   ```sql
   -- 重复挂载
   SELECT wazuh_agent_id, count(*) AS n
   FROM soc_assets
   WHERE wazuh_agent_id IS NOT NULL
   GROUP BY wazuh_agent_id HAVING count(*) > 1;

   -- 同 IP 重复资产（T0b 用，本批次仅观察不修）
   SELECT asset_ip, count(*) FROM soc_assets GROUP BY asset_ip HAVING count(*) > 1;
   ```
2. **清理双挂**：对每一条 `wazuh_agent_id` 重复记录，**以 Wazuh 实际注册 IP 为准**保留正确资产，把错挂的那条 `UPDATE soc_assets SET wazuh_agent_id = NULL WHERE id = <错挂资产>`（不要直接删行，避免丢失端口/标签等关联数据）。若两条都是真实资产但误共享了同一 agent_id，需先确认哪条该绑此 agent——拿不准就**暂停并回报**，不要猜。
3. **加唯一部分索引**（两步走，因 Alembic 当前非权威、用 create_all 启动）：
   - 一次性 SQL：`CREATE UNIQUE INDEX IF NOT EXISTS uq_soc_assets_agent_id ON soc_assets (wazuh_agent_id) WHERE wazuh_agent_id IS NOT NULL;`
   - 前向兼容：在 `asset.py` 的 `Asset` 类上用 `Index('uq_soc_assets_agent_id', 'wazuh_agent_id', unique=True, postgresql_where='wazuh_agent_id IS NOT NULL')` 标注（与现有 `__table_args__` 合并），供后续迁移工具识别。
4. **防回归**：确认 `soc_assets.wazuh_agent_id` 写入逻辑（资产同步服务）不会对同一 agent 重复建资产——若发现会重复创建，在该写入处加"已存在则更新"去重（属顺带加固，非必须）。

**验收标准：**
- 复核查询 1 返回 0 行（无重复挂载）。
- 唯一索引生效：对已清空的那个 agent_id 重新 `INSERT` 同值 → 被索引拒绝（验证可过期后回滚）。
- 无 Agent 资产（`wazuh_agent_id IS NULL`）不受索引约束，仍正常。

**验证方法：** 重跑步骤 1 的两条 SQL；手动尝试重复写被拒（演示后回滚）。
