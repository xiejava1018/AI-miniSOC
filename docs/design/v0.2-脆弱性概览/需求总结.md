# 脆弱性概览 - 需求总结

## 📋 基本信息

- **版本**: v0.2
- **日期**: 2026-03-25
- **模块**: 脆弱性概览页面
- **设计方案**: 方案E（紧凑型卡片）

---

## 🎯 背景和目标

### 痛点
1. **CVE漏洞和配置检查混在一起不够清晰** - 用户无法快速区分两种类型的脆弱性
2. **缺少关键信息** - 无法看到整体安全态势、趋势变化和资产维度的风险分布
3. **信息组织不清晰** - 一级页面应该展示什么信息才能让用户快速了解安全状况

### 目标
重新设计脆弱性概览页面，让用户打开页面就能：
- ✅ 快速了解整体安全态势（总量、严重程度分布）
- ✅ 看到趋势变化（最近变好了还是变差了）
- ✅ 了解哪些资产最脆弱（高风险资产排行）
- ✅ 清晰区分CVE漏洞和配置检查两种类型

---

## 📊 功能范围

### 要做什么
- **CVE漏洞统计卡片**：显示总量 + 严重程度分布（严重、高危、中危）
- **配置检查统计卡片**：显示总量 + 严重程度分布（严重、高危、中危）
- **本周趋势卡片**：显示CVE和配置检查的周变化（百分比、上升/下降）
- **高风险资产排行**：Top 5，显示资产名称、IP、各级别漏洞数量
- **最近发现的CVE**：Top 5，显示CVE编号、标题、影响资产、发现时间
- **最近失败的配置检查**：Top 5，显示配置项名称、影响资产、发现时间

### 不做什么
- ❌ 不做复杂的交互（如拖拽、自定义图表、筛选）
- ❌ 不做深度的分析（如根因分析、关联分析、趋势预测）
- ❌ 不做AI建议详细展示（移到详情页或独立页面）
- ❌ 不做复杂的筛选和搜索（这些功能在列表页）
- ❌ 不做同步操作（在各自的列表页已有）

## 🔑 关键决策

### 1. 布局方案选择
**决策**: 采用方案E（紧凑型卡片）

**理由**:
- 信息密度高，一屏展示所有关键信息
- 三个统计卡片并排显示，CVE和SCA清晰分离
- 配合趋势可视化，用户快速了解态势
- Top 5列表不会让页面过长，保持紧凑

### 2. CVE和配置检查的关系
**决策**: 两个完全独立的统计卡片，独立展示

**理由**:
- 用户需要清楚区分两种类型的脆弱性
- 各自有不同的严重程度分布和处理优先级
- 点击卡片可跳转到对应的详细列表页

### 3. 数据维度选择
**决策**: 展示三个维度 - 统计、趋势、资产

**理由**:
- **统计维度**：回答"有多少问题"（现状）
- **趋势维度**：回答"变好了还是变差了"（变化）
- **资产维度**：回答"哪些资产最危险"（重点）

### 4. 排行榜数量
**决策**: 所有排行都限制为Top 5

**理由**:
- 概览页不展示过多数据，保持简洁
- Top 5足够用户快速识别最需要关注的风险点
- 详细排行在资产列表页或专门的报告中展示

### 5. 交互设计
**决策**: 所有卡片和列表项都可点击，跳转到对应详情页

**理由**:
- 不在概览页提供复杂操作
- 点击后进入详情页进行深度操作
- 保持概览页的简洁性和快速浏览体验

## 🛠 技术约束

### 前端技术栈
- **框架**: Vue 3 + TypeScript
- **UI库**: Element Plus
- **样式**: 遵循现有设计系统（玻璃态风格）
- **路由**: Vue Router

### 后端API需求
需要以下API接口（部分已实现，部分需要新增）：

#### 已有API
- `GET /api/v1/vulnerabilities/stats/overview` - CVE漏洞统计
- `GET /api/v1/vulnerabilities/stats/sca-overview` - 配置检查统计（新增）
- `GET /api/v1/vulnerabilities/vulnerabilities?type=scap&limit=5` - CVE列表
- `GET /api/v1/vulnerabilities/vulnerabilities?type=sca&limit=5` - 配置检查列表

#### 需要新增的API
- `GET /api/v1/vulnerabilities/stats/trend` - 趋势数据（最近7天）
- `GET /api/v1/vulnerabilities/stats/top-assets` - 高风险资产排行（Top 5）
- `GET /api/v1/vulnerabilities/stats/recent?type=cve&limit=5` - 最近发现的CVE
- `GET /api/v1/vulnerabilities/stats/recent?type=sca&limit=5` - 最近失败的配置检查

### 数据格式约束
- 统计数据：`{ critical, high, medium, low, total }`
- 趋势数据：`{ cve: { current, change, change_percent }, sca: { current, change, change_percent } }`
- 资产排行：`[{ rank, asset_id, asset_name, asset_ip, critical_count, high_count, medium_count }]`
- 最近发现：`[{ id, title, asset_name, discovered_at }]`

### 性能要求
- 页面首次加载时间 < 1秒
- 数据刷新时间 < 500ms
- 支持并发请求所有API
- 超时时间：10秒

## 📱 页面状态

### 正常态（有数据）
- 所有统计数据正常显示
- Top 5列表完整渲染
- 卡片可点击，悬停有视觉反馈

### 加载态（数据加载中）
- 显示居中的旋转Spinner
- 显示"正在加载脆弱性数据..."文案
- 所有交互元素禁用
- 超时时间：10秒

### 空态（没有数据）
- 显示友好的图标和引导文案
- 标题："暂无脆弱性数据"
- CTA按钮："立即同步数据"
- 不显示统计卡片和列表

### 错误态（加载失败）
- 显示错误图标和说明
- 根据错误类型显示不同文案：
  - 网络错误："无法连接到服务器"
  - API错误："服务器异常，请稍后重试"
  - 超时："请求超时，请检查网络后重试"
  - 权限错误："没有访问权限，请联系管理员"
- 提供"重新加载"按钮

### 部分可用态（部分数据失败）
- 成功的部分正常显示
- 失败的部分半透明 + 显示"加载失败"标签
- 失败部分显示"--"和重试提示
- 不影响其他可用数据的展示

## 🔄 交互行为规则

### 用户操作

| 操作 | 系统行为 | 反馈 |
|------|---------|------|
| 点击CVE漏洞卡片 | 跳转到 `/vulnerabilities/cve-list` | 页面导航 |
| 点击配置检查卡片 | 跳转到 `/vulnerabilities/sca-list` | 页面导航 |
| 点击"查看完整排行" | 跳转到资产列表，按风险排序 | 页面导航 |
| 点击单个资产行 | 跳转到资产详情页 | 页面导航 |
| 点击最近发现项 | 跳转到详情页 | 页面导航 |

### 系统行为

| 触发 | 系统行为 | 反馈 |
|------|---------|------|
| 页面加载 | 显示加载态 → 并发请求API → 渲染数据 | Spinner → 内容 |
| 数据加载成功 | 更新所有统计数据和列表 | 无（静默） |
| 数据加载失败 | 显示错误态 | 错误Toast |
| 数据为空 | 显示空态 | 空态页面 |
| 部分数据失败 | 失败部分显示"加载失败" | 警告Toast |
| 网络超时 | 取消请求，显示超时错误 | 错误Toast |

### Toast规则

| 类型 | 位置 | 时长 | 示例 |
|------|------|------|------|
| 成功 | 页面顶部居中 | 2秒 | "同步完成！新增23个CVE漏洞" |
| 错误 | 页面顶部居中 | 5秒 | "同步失败：网络连接超时" |
| 警告 | 页面顶部居中 | 3秒 | "Wazuh中暂无CVE漏洞数据" |

**同时显示限制**: 最多3条，超过则排队
